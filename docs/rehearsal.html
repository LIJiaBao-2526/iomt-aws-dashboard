公開網站專題報告虛擬 ESP32

四人進度展示操作與講稿

建議總長 6–8 分鐘，一部電腦接投影，按 CHAN → LI → LEE → KWOK 順序交接。以下說明各人的負責模組，不代表虛構的個人完成紀錄；不熟悉的程式請先跟着操作排練。

展示前先準備

在專案目錄開兩個終端。第一個啟動網站服務，第二個啟動 MQTT 橋接器。若本機網站已能打開且橋接器正在運作，就不要重複啟動。

第一個終端：
python backend/server.py

第二個終端：
python tools/mqtt_bridge.py

這部電腦也可雙擊專案內的 Start_Local_Server.cmd 及 Start_MQTT_Bridge.cmd。然後開好下面三頁：

  1. Wokwi 虛擬裝置：暫時停在未啟動狀態，或保持原來正在執行的同一頁；不要同時啟動兩份。
  2. 本機即時儀表板：選「本機資料庫」，勾選每五秒更新。
  3. GitHub 程式倉庫：準備展示各自負責的檔案。

注意：公開 Pages 網址只展示獨立情境，不能讀取這部電腦的 SQLite；現場 Wokwi 連動務必使用 127.0.0.1:8877。

01 · CHAN Ka Ming · 裝置與資料採集 · 約 90 秒

展示虛擬 ESP32 和旋鈕

  1. 打開 Wokwi，指出 ESP32、旋鈕及 GPIO34 綠色訊號線。
  2. 點綠色 Play；如果已在運作，不必重啟。指出下方 Serial Monitor 的 WiFi／MQTT 連線及 PUBLISHED 訊息。
  3. 點旋鈕本體，按鍵盤 End，讓心率升到 150。保持這個值，交給 LI。
「我負責裝置資料採集部分。我們沒有實體感測器，所以用 Wokwi 執行虛擬 ESP32。旋鈕代表合成心率輸入，GPIO34 的數值映射成 50 至 150 bpm，每兩秒透過 MQTT 發送一次。現在把旋鈕調高，下一位會展示資料如何進入後端。這不是人體量測。」

可展示程式：wokwi/main.py 的 ADC(Pin(34))、bpm = 50 + ...、client.publish。

02 · LI Jia Bao · 後端與資料庫 · 約 90 秒

展示橋接與資料儲存

  1. 切到橋接器終端，指出 STORED 150 bpm 和 UTC 時間。
  2. 打開 本機 API JSON，指出 heart_rate、timestamp、synthetic。
  3. 簡述 mqtt_bridge.py 轉成 HTTP POST，server.py 驗證後寫 SQLite。
「我負責資料接收和儲存。虛擬 ESP32 把合成值送到 MQTT，我的橋接程式只接收指定 topic 和合法範圍，再透過本機 API 寫入 SQLite。記錄帶有時間與 synthetic 標記，相同記錄重送不會新增副本。AWS 架構及部署程式也有保留，但原 Learner Lab 課程已結束，今天實際運作的是本機路徑。」

如果被問為甚麼不用 AWS：「目前課程資源不能進入，因此先驗證可重現的裝置至網站流程，下一階段用新的有效 Lab 恢復雲端部署。」

03 · LEE Tsz Him · 前端與資料視覺化 · 約 90 秒

展示網站即時更新及匯出

  1. 切到本機儀表板，確認來源是 SQLite，勾選每五秒更新。
  2. 等待約十秒，指出 150 bpm、圖表及最後三筆偏高的提示。
  3. 點「下載 CSV」，打開檔案，指出資料值及 sqlite_synthetic 來源。
  4. 如需展示跨電腦網址，再開公開 Pages，明確說它是獨立的瀏覽器情境。
「我負責網站與視覺化。頁面顯示最新心率、平均值、時間、趨勢和記錄，並可每五秒重新讀取資料庫。剛才旋鈕送出的數值已顯示在這裡。當最後三筆都大於 100，而且間隔不超過兩分鐘，就顯示規則提示。資料也能匯出 CSV；這是展示規則，不是疾病診斷。」

可展示程式：docs/app.js、docs/style.css。保持本機資料庫模式，不要按本頁情境按鈕覆蓋即時來源。

老師常問的問題

問題直接回答
是真實心率嗎？不是，是旋鈕控制的合成資料；裝置程式及資料流程是真正在運作。
現在有 AI 嗎？有知識檢索及 DeepSeek 介面；目前沒有 key，今天不展示真實生成。
AWS 有運行嗎？現在沒有，原 Lab 課程已結束；部署程式與雲端設計已保留。
為甚麼選 MQTT？用發布／訂閱方式分開裝置與接收端，橋接器把訊息轉給現有 HTTP API。
100 bpm 是診斷標準嗎？不是，是本專題測試規則，未經臨床驗證。
你們四個各完成甚麼？按負責模組說明，並展示自己理解的程式；實際編寫及工具協助的情況照實說。

臨場出錯時

Wokwi 連不上：等十秒，查看 WiFi 狀態；只啟動一個模擬工程。橋接器無資料：確認終端顯示 MQTT subscribed，然後旋鈕仍在運作。網站不更新：確認網址是本機、選中本機資料庫並勾選刷新。公共 broker 不穩時，改執行 python tools/simulator.py --scenario high --interval 1，並明說臨時改用 Python 模擬資料，不能說仍由 ESP32 傳來。

需要清除偏高提示時，在 Wokwi 點旋鈕再按 Home，送入 50 bpm；等待三筆新資料及網頁刷新。停止／重啟模擬不會自動清除資料庫歷史。

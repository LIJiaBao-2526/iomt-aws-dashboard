Pulse 雲端心率監測與檢索問答系統

本專題示範接收合成心率、儲存時間序列、以網頁顯示趨勢及解釋展示規則。交付包含可執行的本機接收流程、GitHub Pages 展示、AWS 部署程式、來源明確的問答及測試。依所選交付範圍，實體感測器與真實 DeepSeek 呼叫未納入驗收，程式保留後續整合介面。

四人進度展示操作與講稿 · Wokwi 虛擬 ESP32 工程

本次新增並實測：虛擬 ESP32 讀取旋鈕，將合成 75／150 bpm 經公共 MQTT broker 傳給本機橋接器，再寫入 SQLite，網站自動更新並觸發規則。這不是實體生理感測器。橋接器以接收時間標記資料；公共 broker 僅供合成資料演示。

一 目的與使用情境

情境是照顧者在瀏覽器查看量測記錄、理解最新值及變化，再查看何時觸發預設規則。本版本使用合成資料，重點為資料工程、雲端架構、可解釋展示和故障處理。沒有宣稱疾病預測、臨床準確度或替代醫護判斷。

GitHub Pages 提供跨電腦分享的網頁；AWS API Gateway、Lambda 及 DynamoDB 是雲端讀取架構。本機標準庫伺服器提供可重現的接收和儲存流程，讓演示在 Learner Lab 不可用時仍能完成。

二 系統架構

本機：HTTP 模擬器 → 驗證 → SQLite → 網站 → 規則與問答
雲端設計：IAM 保護寫入 → DynamoDB → Lambda → API Gateway → GitHub Pages
問答：問題 → 關鍵字檢索 → 合成統計與來源 → 可選 DeepSeek

本機伺服器只監聽 127.0.0.1。公開網站的情境不寫入資料庫，也不冒充 AWS 資料。AWS 只讀取固定保留的合成系列。本機資料庫模式可從伺服器環境設定 DeepSeek key；公開 Pages 僅使用檢索，沒有付費 AI 接口。

三 資料與接口

{"device_id":"website-synthetic-demo",
 "timestamp":"2026-11-12T01:00:00+00:00",
 "heart_rate":78,"synthetic":true}

裝置及 UTC 時間組成主鍵。心率須為有限數值，工程輸入範圍是 20 至 250 bpm；時間必須附時區，且不可超前伺服器五分鐘。範圍不是健康參考標準。相同記錄重送不新增副本，同一主鍵的不同內容會被拒絕。只接受保留裝置及明確合成資料。

本機接口用途主要回應
GET /api/health檢查本機服務200
POST /api/readings接收合成讀數201 新增、200 已存在、400 格式或衝突
GET /api/demo最近 60 筆，按時間排序200 合成記錄
POST /api/analyze提交 question 問題回答、模式、來源、統計

伺服器限制同源、JSON 類型及 8 KB 內容大小。錯誤不暴露密鑰或供應商內部訊息。SQLite 的資料在服務重新啟動後仍存在，保存在 Git 忽略的 .local 資料夾。

四 規則與檢索問答

展示規則為最後三筆心率均大於 100 bpm，且相鄰間隔大於零並不超過兩分鐘。100 本身不觸發；不足三筆或長時間缺資料不能代表持續偏高。自然語言提示來自明確軟件規則，不是醫療判斷。

知識庫包含系統架構、展示規則、NHS 心悸衛教摘要和 DeepSeek 接口說明。以中英文關鍵字匹配，依命中數排序並取最多三組來源。此為小型關鍵字檢索，沒有向量資料庫或模型訓練；沒有來源支持時會說資料不足。

本機如有 API key，會把問題、合成統計與來源送到 DeepSeek 生成。缺少 key 或供應商錯誤會明確顯示檢索模式。mock 測試只驗證接口流程，不能當作真實模型回應已驗證。任何生成文字仍需人工覆核，不作個人診斷或用藥建議。
